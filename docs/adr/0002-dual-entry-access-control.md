# ADR-0002：文档同时提供永久链接与受控分享链接，用可见性字段界定二者关系

- 状态：Accepted
- 决策时间：2026-08-25 17:33:40 +08:00
- 负责人：项目所有者
- 关联 Spec/Ticket：`docs/specs/0001-online-document-sharing.md`
- 替代/被替代 ADR：无

## 背景

产品需要把文档分享出去。有两种入口形态：

- 永久链接 `/d/{slug}`：稳定、可读、适合公开传播。
- 分享链接 `/s/{token}`：不可枚举，可设密码与有效期，可随时停用，可按渠道分别统计。

项目所有者要求两种入口都要有：既想把某些文章公开发到社交媒体拉流量，也想把方案类文档带密码发给特定客户。

两者共存会产生一个安全陷阱：如果一个文档既能通过永久链接公开访问，又存在一条设了密码的分享链接，管理员会自然地认为"这份文档受密码保护"，而实际上任何人都能绕过密码从永久链接读到全文。这类误判在分享商业文档的场景下代价很高。

## 决策

给文档增加基础可见性字段 `visibility`，取值 `private` 或 `public`，把两种入口从并列关系改为从属关系：

- `visibility = private`：`/d/{slug}` 返回 404，与文档不存在的表现完全一致。文档只能通过分享链接访问，每条链接的密码与有效期真正生效。
- `visibility = public`：`/d/{slug}` 任何人可访问。分享链接退化为带统计能力的渠道标记，其密码与有效期**不具备约束力**。

配套三条强制要求：

1. 创建或编辑分享链接时，若目标文档为 `public`，界面必须显示明确警告：该文档已公开，任何人可通过永久链接直接访问，此处设置的密码和有效期不会限制永久链接。
2. 访问控制判定集中在 `src/server/documents/access.ts`，是唯一权威位置。阅读端页面不得自行拼装可见性判断。
3. `allow_index`（允许搜索引擎索引）只有在 `visibility = public` 且 `status = published` 时才允许为 true，其余一律输出 `noindex`。

统计上，永久链接的访问记为 `view_logs.share_link_id = NULL`，在后台作为名为"永久链接"的伪渠道与其他分享链接并列展示。

## 备选方案

1. **只保留分享链接**：所有对外访问统一走 `/s/{token}`，文档本身不直接暴露。
2. **只保留永久链接**：一个文档一个链接，不支持多渠道。
3. **两者共存但不加可见性字段**：靠文档说明提醒管理员注意，不在数据模型上区分。

## 选择理由

方案 1 在安全性上最干净，统计口径也最统一，是初始推荐方案。但它无法满足"公开发文章拉流量"的需求——`/s/{token}` 这种随机串链接既不适合公开传播，也不适合被搜索引擎收录。产品需求真实存在，不应为了实现简单而砍掉。

方案 2 放弃了按渠道统计和单独撤销的能力，而这正是本产品相对于"直接发文件"的核心价值。

方案 3 是最危险的选项。它把一个结构性问题降级成文档提醒，而管理员在忙碌时不会去查文档。安全默认值必须由系统保证，不能依赖人的记忆。

本决策的实质是：承认两种入口的能力差异，把它编码进数据模型（`visibility` 字段），并在管理员可能误判的那一刻（创建分享链接时）主动提示。密码在 `public` 文档上失效这件事本身无法消除——公开就是公开——能做的是确保管理员知道它失效。

## 影响与风险

- 正面影响：两种分享场景都被满足；`private` 是默认值，符合安全默认原则；访问控制逻辑集中，便于测试与审查。
- 负面影响：`public` 文档上的分享链接密码是"装饰性"的，这是一处反直觉行为，必须靠界面警告和文档持续说明。新加入的维护者可能不理解为什么两种入口的密码语义不同。
- 安全影响：默认 `private` + 默认 `noindex` 构成安全默认值。风险点是管理员把文档设为 `public` 后忘记它上面还有"受保护"的分享链接，缓解手段是创建链接时的强制警告。
- 性能影响：`/d/{slug}` 与 `/s/{token}` 是两条路由但共用同一套渲染逻辑，无额外成本。
- 运维影响：无。

## 迁移与回滚

首次建模。`visibility` 有默认值 `private`，即使将来需要回退到"只有分享链接"的方案，只需把所有文档置为 `private` 并下线 `/d/{slug}` 路由，不涉及数据迁移。

## 验证方式

- 单元测试覆盖访问控制判定矩阵：`visibility` × `status` × `deleted_at` × 链接状态（不存在/停用/过期/需密码/正常）的组合。
- 手工验证：`private` 文档的 `/d/{slug}` 返回 404，且与真实不存在的 slug 表现一致（不能通过响应差异探测文档是否存在）。
- 手工验证：把文档从 `private` 改为 `public` 后，创建分享链接的界面出现警告。

## 后续事项

- 管理端文档列表需要用醒目的 badge 区分 `private` 与 `public`，避免管理员误判当前状态。
- 若将来出现"公开但要求登录"的第三种可见性，需重新评估本 ADR。
