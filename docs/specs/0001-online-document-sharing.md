# 规格：在线文档阅读与分享

- 状态：Approved
- 风险等级：L3
- 创建时间：2026-08-25 17:30:12 +08:00
- 最后更新时间：2026-08-25 17:30:12 +08:00
- 负责人：项目所有者（单管理员）

## 背景与问题

需要一个能把 Markdown 文档发布成网页链接、分享给外部读者阅读，并统计浏览量的系统。现有做法（发文件、发截图、用第三方文档平台）存在三个问题：无法统计谁看了、无法撤销已发出的内容、排版在不同设备上不可控。

本系统解决这三点：把文档托管在自己的服务上，通过链接对外分享，链接可设密码与有效期并随时停用，同时记录浏览量。

## 目标

1. 管理员在后台以 Markdown 撰写、编辑和发布文档。
2. 外部读者无需注册，通过链接直接阅读，阅读体验以内容为中心。
3. 分享链接支持密码、有效期和随时停用；一个文档可生成多条链接，分别统计。
4. 记录 PV 与 UV，提供按天趋势与文档排行。
5. 后台可查看文档列表、分享链接状态与浏览统计。

## 非目标

- 多用户与角色权限。系统按单管理员设计，数据模型预留 `author_id` 但不实现 RBAC。
- 文档合集/知识库（多文档组成一本手册）。一期用分类与标签兜住。
- 上传 PDF/Word 解析。内容来源只有后台 Markdown 编辑器。
- 评论、点赞、收藏等互动功能。
- 全文检索。文档量在单管理员场景下用数据库 `LIKE` 足够。

## 用户场景

**场景 A：对外分享一份方案**
管理员写完文档并发布，为客户甲生成一条带密码、7 天有效期的分享链接，把链接和密码分别发给对方。客户打开链接，输入密码后阅读。三天后管理员在后台看到这条链接被打开了 4 次。项目结束后管理员停用该链接，对方再打开时看到"链接已停用"页面。

**场景 B：公开一篇文章**
管理员把文档可见性设为公开并允许搜索引擎索引，将永久链接 `/d/{slug}` 发到社交媒体。读者点开直接阅读，浏览量计入"永久链接"这个渠道。

**场景 C：对比两个渠道的效果**
管理员为同一份文档生成两条链接，备注分别是"发给 A 公司"和"发给 B 公司"。一周后在后台看到 A 公司的链接被打开 12 次而 B 公司 0 次，据此判断跟进优先级。

## 受影响模块与架构

全新项目，模块划分与依赖方向见项目 `AGENTS.md` 的「目录路由」和「架构约束」。核心模块：

- `src/server/auth/`：密码哈希、会话签发校验、DAL。
- `src/server/documents/`：文档领域逻辑，访问控制判定的唯一权威位置在 `access.ts`。
- `src/server/markdown/`：Markdown 渲染与 HTML 净化管线。
- `src/server/analytics/`：浏览量记录与聚合（第四期）。
- `src/app/(reader)/`：公开阅读端。
- `src/app/(admin)/admin/`：后台管理端。

## 功能与行为要求

### 访问控制模型

文档有基础可见性 `visibility`，取值 `private` 或 `public`：

- `private`：`/d/{slug}` 返回 404。文档只能通过分享链接访问，每条链接的密码与有效期真正生效。
- `public`：`/d/{slug}` 任何人可访问。此时分享链接退化为带统计的渠道标记，其密码**不具备约束力**。

这是有意为之的取舍，理由与备选方案见 `docs/adr/0002-dual-entry-access-control.md`。为避免管理员误判，创建或编辑分享链接时，若目标文档为 `public`，界面必须显示明确警告：该文档已公开，任何人可通过永久链接直接访问，此处设置的密码和有效期不会限制永久链接。

`allow_index`（是否允许搜索引擎索引）默认为 false，且只有在 `visibility = public` 且 `status = published` 时才允许置为 true。其余情况一律输出 `noindex`。

### 分享链接

- token 由 `nanoid(22)` 生成，不可枚举。
- 每条链接可独立设置备注、密码、有效期，并可随时停用。
- 拦截优先级：链接不存在 → 404；已停用 → 停用页；已过期 → 过期页；需要密码且未通过校验 → 密码页；否则渲染文档。
- 密码校验通过后，在该链接的作用域内建立短期凭证，避免每次刷新都要重新输入。

### 文档管理

- 状态流转：`draft` → `published` → `archived`。仅 `published` 可被外部访问。
- 删除为软删除（写 `deleted_at`），软删除后所有入口立即失效。
- Markdown 内容在保存时于服务端渲染并净化，结果存入 `content_html`，阅读页直接读取，不在请求时解析。

### 浏览量统计

- PV 为每次打开加一；UV 按访客去重，同一访客对同一文档在 30 分钟窗口内只计一次。
- 访客身份用 `localStorage` 中的匿名 UUID，配合 `hash(IP + UA)` 兜底。
- 阅读页渲染请求内不做计数写入，页面加载后由前端异步上报。写入路径的设计与理由见 `docs/adr/0003-view-count-write-path.md`。
- 永久链接的访问记为 `view_logs.share_link_id = NULL`，在后台作为名为"永久链接"的伪渠道展示。

## 错误、边界与失败行为

| 情况 | 行为 |
|---|---|
| 文档不存在、已软删除、非 published | 404 页面，不区分原因，避免探测 |
| `private` 文档的 `/d/{slug}` | 404，与不存在的文档表现一致 |
| 分享链接 token 不存在 | 404 |
| 分享链接已停用 | 专门的停用页，说明链接已失效并提示联系分享者 |
| 分享链接已过期 | 专门的过期页，同上 |
| 分享链接需要密码 | 密码输入页，错误时在字段旁提示，不透露文档任何信息 |
| 登录失败 | 统一提示"用户名或密码错误"，不区分用户不存在与密码错误 |
| 埋点上报失败 | 静默失败，绝不影响阅读 |
| Markdown 渲染失败 | 保存操作失败并返回可读错误，不写入半成品 `content_html` |

## 数据、接口与兼容性

数据模型见 `prisma/schema.prisma`，为唯一权威来源。设计要点：

- MySQL 8，字符集 `utf8mb4` / `utf8mb4_0900_ai_ci`，否则标题中的 emoji 会写入失败。
- `view_logs.share_link_id` 可空，`NULL` 表示永久链接入口。
- `doc_daily_stats` 用 `(document_id, share_link_id, stat_date)` 做主键，而 MySQL 主键不允许 NULL，故该表用 `0` 表示永久链接。这是与 `view_logs` 不一致的地方，聚合任务负责转换。
- `documents.view_count` / `uv_count` 为冗余计数，读多写少，允许最多一分钟延迟。
- 图表数据一律查 `doc_daily_stats`，不在 `view_logs` 上做 `GROUP BY`。

对匿名访客开放的唯一写接口是 `POST /api/view`，属于公共契约，变更需同步埋点脚本与限流策略。

首次建模，无向后兼容负担。后续 Schema 变更按 expand-migrate-contract 分阶段执行。

## 安全、隐私与权限

- **XSS**：Markdown 允许内嵌原生 HTML，若不净化则任何能编辑文档的人可在公开页注入脚本。管线固定为 `remark-rehype`（不开 `allowDangerousHtml`）→ `rehype-sanitize` → `rehype-stringify`，且净化只在服务端执行。语法高亮若引入，必须排在净化之后，对已净化的文本重新生成可信标记。
- **链接枚举**：分享 token 用 `nanoid(22)`，禁止自增 ID。
- **会话**：JWT 存 httpOnly cookie，`sameSite=lax`，生产 `secure=true`。载荷只放用户 ID 与过期时间，不放任何敏感信息。
- **授权**：`proxy.ts` 只做基于 cookie 的乐观重定向。每个受保护的数据访问和 Server Action 必须独立调用 DAL 校验会话，不以中间件为唯一防线。
- **密码**：bcrypt 哈希存储，登录失败信息不区分原因。
- **隐私**：`view_logs` 记录 IP 与 UA 属于个人信息，保留 90 天后由定时任务清理，日聚合表不含个人标识可永久保留。
- **防刷**：同一 IP 对同一文档 1 分钟内多次上报只计一次，过滤已知爬虫 UA，上报接口限流。

## 性能与可观测性

- 阅读页 SSR，`content_html` 预渲染落库，请求内不解析 Markdown。
- 浏览量走 Redis 计数 + 定时批量回写，避免热点行锁阻塞阅读页首屏。
- 统计图表查预聚合表，`view_logs` 仅用于明细查询并按 `(document_id, created_at)` 建索引。
- 关键操作（登录、发布、链接停用、埋点失败）需要可定位日志，且不得记录密码、token 或完整 IP 之外的敏感信息。

## 验收标准

一期（本次交付）的验收标准以 `DEVLOG.md` 中「验收标准」小节为准。后续各期在实现前补充对应条目。

## 测试与验证计划

- 单元测试覆盖：Markdown 净化（脚本标签、事件属性、`javascript:` 协议链接）、访问控制判定矩阵、会话签发与校验、密码哈希与校验。
- 集成验证：Prisma 迁移在真实 MySQL 容器上执行成功；登录、发布、访问三条主链路手工走通。
- 界面验证：阅读端与管理端在 375px、768px、1440px 三个视口实际渲染检查。
- 安全验证：构造含 `<script>`、`<img onerror>`、`javascript:` 链接的 Markdown，确认渲染结果无可执行内容。

## 迁移、发布与回滚

一期不发布。Prisma 首次迁移仅创建新表，无历史数据，回滚方式为删除迁移目录并重建数据库。

上线前置条件（阻塞项）：域名注册、ICP 备案（国内服务器必需，通常 1-2 周）、HTTPS 证书。分享链接在微信内打开需要 HTTPS。
